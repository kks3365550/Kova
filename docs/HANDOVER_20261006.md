## 5. 오프사이트 백업 구축 (신규)

### 발견 과정

NAS가 아니라 **사내 다른 PC**였습니다. `\\품관김기수\k12백업` 공유 폴더가 이미 백업 전용으로 존재합니다.

```

Y: → \\품관김기수\바탕화면
Z: → \\품관김기수\품질관리팀
```

### robocopy 채택 근거 (실측)

| 방법 | 341개 소요 | 84,192개 환산 |
|---|---:|---:|
| **robocopy /MT:32** | **1.5초** | **12분** |
| Python `Copy-Item` | 26.3초 | 108분 |
| Python + icacls | 약 78초 | 약 20시간 |

`core/replication.py`가 블록마다 `icacls`를 subprocess로 호출해 SMB 상에서 블롭당 239ms를 소요했던 것이 원인입니다.

### 구현

```
core/offsite.py        robocopy 복제 엔진 (신규 259줄)
cli_backup.py          백업 성공 후 복제 단계 추가
data/profiles.json     offsite_repo_dir (UNC), timeout 7200초
tests/test_offsite.py  회귀 테스트 10건 (신규)
```

설계 원칙: **복제 실패가 로컬 백업 결과를 훼손하지 않음** (격리된 예외 처리)

### 실증 결과

```

Ed25519 서명 검증: True
```

### 개발 중 발견한 함정 2개

1. **robocopy는 로케일별 출력** — 한글 환경에선 `"파일"` (영문 `Files`가 아님)
2. **`encoding="utf-8"` 지정 시 cp949 출력이 깨짐** — 요약 파싱이 전부 0 반환

## 6. 주요 설계 결정

| 결정 | 이유 |
|---|---|
| robocopy 채택 (replication.py 수정 대신) | 17~190배 성능 차이. icacls 병목은 증상일 뿐 Python I/O 방식 자체가 병목 |
| UNC 경로 사용 (`\\서버\공유`) | S4U 서비스 세션에서도 동작. 드라이브 문자는 세션 종속 |

| WORM 철회 | `protect_repository()` 호출부 0건으로 3년간 미작동. 켜면 자기 GC와 충돌 |
| 서버 `127.0.0.1` 바인딩 | 복원·삭제 API가 있어 사내망 노출 불필요 |

## 9. 작업 중 발생한 오해와 교정

오늘 수정한 실수를 기록합니다. 같은 실수 반복 방지를 위함입니다.

| 잘못한 판단 | 실측 결과 |
|---|---|
| "WORM이 자기 GC를 막는다" | 작동함. `unprotect_file` 경로가 이미 존재 |
| "디렉토리 DC Deny는 무의미" | 파일별 `(DE,WD,AD)` Deny가 핵심 |
| "ACL 적용에 18분" | `icacls /T`면 40초 |
| "미커밋 6개 남아있다" | 이미 v2.13.5에 커밋됨 |
| "`except e`만 정리하면 됨" | NameError를 새로 유발 |
| "테스트 통과를 믿으면 됨" | 에이전트 격리 venv에서 실행되어 재현 불가 |

**교훈**: 추측 대신 실측. 외부 모델 분석(에이전트 venv, Qwen)은 반증 재료로만 사용하고 최종 판단은 현장 실측으로 합니다.
