## 완료된 것

### web/state.py
`current_task`, `task_lock`, `append_task_log` 의 유일한 소유자가 된다.

라우터로 나누면 상태가 각 모듈에 흩어져 "백업 중인데 복원이 동시에 시작되는"
사고가 난다. 한 곳에 두면 라우터 추가/제거가 상태에 영향을 주지 않는다.

제공 함수:
```
try_begin_task(type, progress) -> bool   # 이미 실행 중이면 False
finish_task(result, error)
snapshot_task_status() -> dict            # UI 직렬화용
request_cancel() -> bool
get_task_logs(limit)
```

### web/api_auth.py
인증 6개 엔드포인트를 `APIRouter` 로 분리했다.
경로 계약 `/api/auth/*` 는 그대로 유지된다.

인증 **미들웨어**는 app.py 에 남겼다. 앱 전체에 적용되어야 하며 라우터로
옮기면 정적 리소스 보호가 빠진다.

## 왜 나머지는 중단했는가

Update 구간을 기계적으로 추출하려 했을 때 pyflakes 가 40개 이상의 결함을
즉시 드러냈다:

```
api_update.py:72:33   undefined name 'BASE_DIR'
api_update.py:173:51  undefined name 'VERSION'
api_update.py:310:23  undefined name '_cached_update_info'
api_update.py:342:47  undefined name 'BackgroundTasks'
api_update.py:346:9   undefined name 'append_task_log'
api_update.py:95:5    redefinition of unused 'zipfile'
api_update.py:233:5   redefinition of unused 'check_for_update'
... 총 40건
```

원인은 추출한 구간이 앱 전역 심볼에 강하게 묶여 있기 때문이다.

| 심볼 | 정의 위치 | 사용처 |
|---|---|---|
| `BASE_DIR` | app.py:37 | 17곳 |
| `VERSION` | app.py:64 (동적 계산) | Update 구간 6곳 |
| `_cached_update_info` | app.py:83 | Update 구간 6곳 |
| `append_task_log` | web/state.py | Update 구간 4곳 |
| `BackgroundTasks` | fastapi | Update 구간 |
| `zipfile` / `subprocess` / `check_for_update` | 구간 내 재정의 | |

기계적 추출로는 이 의존성을 만족시킬 수 없다.
먼저 상수와 캐시를 별도 모듈로 옮기고 → 라우터가 import 하도록 → 그다음
추출하는 3단계가 필요하다. 각 단계마다 회귀 검증이 있어야 하므로
**여러 세션에 걸쳐 진행할 작업**이다.

무모하게 끝까지 밀어붙였다면 동작하지 않는 코드가 커밋될 뻔했다.
(오늘 이미 `core/scheduler.py` 에서 NameError 를 만들어낸 적이 있다.)

## 이어서 작업하려면

1단계  web/paths.py 생성 (BASE_DIR, STATIC_DIR, TEMPLATES_DIR 이동)

3단계  위 두 모듈로 app.py 참조 치환 + 테스트 통과 확인
4단계  web/api_snapshots.py 추출 (list_snapshots, _get_all_candidate_repos 포함)

## 주의 (FastAPI 0.141)

`include_router` 가 lazy `_IncludedRouter` 로 등록된다.
`app.routes` 를 직접 순회하면 분리된 라우터가 보이지 않는다.

```python
for r in app.routes:
    orig = getattr(r, "original_router", None)   # <- 이게 핵심
    if orig is not None:
        ... orig.routes ...
```

이 패턴을 쓰지 않으면 경로가 사라진 것처럼 오판한다.
(검증 중 실제로 한 번 오판했다. HTTP 200 응답을 확인해 바로잡았다.)
